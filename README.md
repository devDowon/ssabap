# SSAFY 점심 식단 Mattermost 봇

평일 11:30에 오늘 점심 메뉴를 사진과 함께 표 한 장으로 정리해서 Mattermost 채널에 올려주는 봇입니다.
메뉴는 웰스토리(웰플러스 앱)에서 가져오고, GitHub Actions에서 자동으로 실행되므로 따로 서버를 띄울 필요가 없습니다.

**올라가는 메시지 모양**

| (사진) | (사진) | (사진) | … |
|---|---|---|---|
| **브라운그릴** | **동방식객** | **별미공방** | … |
| 연어구이&브로콜리,컬리플라워 (925kcal) | 수엔_유니자장면 (1,020kcal) | 나주곰탕&당면사리 (1,003kcal) | … |
| 캘리포니아라이스 / 호밀브레드 / … | 짬뽕국 / 만두튀김&간장 / 단무지 | 흰쌀밥 / 고추장떡&간장 / … | … |

**준비물**

- 웰플러스 앱 계정 (아이디/비밀번호)
- 메뉴를 올릴 Mattermost 채널
- GitHub 계정

## 시작하기 (약 10분)

### 1. 레포 복사

이 페이지 위쪽의 **Use this template → Create a new repository**를 누릅니다.
Repository name은 아무거나 입력하고, **Private**를 선택한 뒤 **Create repository**를 누릅니다.

> 이후 설명의 "내 레포"는 여기서 만든 레포를 말합니다.

### 2. Mattermost 웹훅 URL 만들기

봇이 메시지를 보낼 주소입니다.

1. Mattermost 왼쪽 위 메뉴(☰) → **통합(Integrations)** → **Incoming Webhooks** → **Add Incoming Webhook**
2. 제목(예: `점심봇`)을 입력하고, 메뉴를 올릴 **채널**을 고른 뒤 저장
3. 화면에 나온 `https://meeting.ssafy.com/hooks/xxxxxxxx` 주소를 복사

주의할 점:

- 브라우저 주소창의 채널 주소(`…/channels/채널이름`)가 아닙니다. `/hooks/`가 들어간 주소여야 합니다.
- 이 주소를 알면 누구나 그 채널에 글을 쓸 수 있습니다. 다음 단계의 Secret에만 넣고 다른 곳에 올리지 마세요.
- 통합 메뉴가 안 보이면 그 팀에서 웹훅 만들기가 막혀 있는 것입니다. 팀 관리자에게 요청하세요.

### 3. Secret 3개 등록

내 레포의 **Settings → Secrets and variables → Actions → New repository secret**에서 아래 3개를 하나씩 추가합니다.
이름은 대소문자까지 똑같이 써야 합니다.

| Name | Secret (값) |
|---|---|
| `WELSTORY_USERNAME` | 웰플러스 앱 아이디 |
| `WELSTORY_PASSWORD` | 웰플러스 앱 비밀번호 |
| `MM_WEBHOOK_URL` | 2단계에서 복사한 웹훅 URL |

여러 채널에 올리고 싶으면 채널마다 웹훅을 만들고, `MM_WEBHOOK_URL`에 쉼표로 이어서 넣습니다.
예: `https://meeting.ssafy.com/hooks/aaa,https://meeting.ssafy.com/hooks/bbb`

### 4. Actions 켜기

내 레포의 **Actions** 탭을 엽니다.

- 초록색 **I understand my workflows, go ahead and enable them** 버튼이 보이면 누릅니다.
- 왼쪽 목록의 **Lunch menu**를 눌렀을 때 "This workflow was disabled" 안내가 보이면 **Enable workflow**를 누릅니다.

둘 다 안 보이면 이미 켜진 상태입니다.

### 5. 테스트 실행

1. **Actions → Lunch menu → Run workflow**를 누릅니다.
2. **dry_run**에 체크하고 초록색 **Run workflow**를 누릅니다.
3. 1분 정도 뒤 실행 기록을 열어 **식단 조회 및 전송** 단계 로그에 메뉴 표가 나오면 성공입니다.

`dry_run`은 채널에 아무것도 보내지 않는 확인용 실행입니다. 주말이나 휴일에는 메뉴가 없어서 `식단 없음`만 나옵니다.

**끝났습니다.** 이제 평일 11:30마다 자동으로 올라갑니다.
오늘 11:30 전에 여기까지 마쳤다면 오늘부터 올라갑니다.
첫날은 11:45쯤 채널을 확인하고, 안 올라왔으면 [직접 실행하기](#직접-실행하기)를 참고하세요.

## 매일 어떻게 동작하나

1. 평일 11:30(한국 시간)에 실행됩니다.
2. 오늘 점심 메뉴를 가져옵니다. 메뉴가 없는 날(주말, 휴일)은 아무것도 보내지 않고 끝납니다.
3. 모든 코스에 사진이 올라와 있으면 바로 보냅니다.
4. 사진이 빠진 코스가 있으면 5분마다 다시 확인합니다. 11:40까지 다 안 올라오면 있는 사진만 넣어서 보냅니다.
5. 하루에 한 번만 보냅니다. 같은 날 다시 실행해도 이미 보낸 채널은 건너뜁니다.

메시지의 표에는 **점심 코스만** 들어갑니다 (테이크아웃, 코인 메뉴 제외).
라면처럼 여러 개 중 고르는 코스는 칼로리를 빼고 토핑 목록만 보여줍니다.

> **실행이 늦을 수 있습니다.** GitHub의 예약 실행은 몇 분에서 수십 분 늦게 시작되는 일이 흔하고, 아주 가끔은 건너뛰기도 합니다.
> 꼭 올라가야 하는 날 안 올라왔으면 직접 실행하세요.

## 직접 실행하기

**Actions → Lunch menu → Run workflow**에서 옵션을 고르고 실행합니다. 아무것도 체크하지 않으면 정기 실행과 똑같이 동작합니다.

| 옵션 | 언제 쓰나 |
|---|---|
| `dry_run` | 채널에 보내지 않고 로그로만 확인하고 싶을 때. 전송 기록을 남기지 않음 |
| `no_wait` | 사진을 기다리지 않고 지금 바로 보내고 싶을 때. **오늘 메시지가 안 올라왔을 때는 이것만 체크** |
| `force` | 오늘 이미 보냈는데 한 번 더 보내고 싶을 때. 같은 메시지가 또 올라감 |
| `date` | 다른 날짜 메뉴를 볼 때. `20261110`처럼 입력 (보통 `dry_run`과 같이 사용) |

직접 보낸 뒤에 늦어진 정기 실행이 돌아도, 하루 한 번 기록 때문에 중복으로 올라가지 않습니다.

## 설정 바꾸기

### 실행 시간

내 레포의 `.github/workflows/lunch.yml`에서 아래 줄을 고칩니다. 시간은 **UTC**라서 한국 시간에서 9시간을 빼야 합니다.

```yaml
- cron: '30 2 * * 1-5'   # 분 시 * * 요일 → 평일 02:30 UTC = 11:30 한국 시간
```

예: 11:00에 올리려면 `'0 2 * * 1-5'`, 12:00에 올리려면 `'0 3 * * 1-5'`.
사진 마감 시각(11:40)은 `lunch_bot.mjs`의 `DEADLINE_HM`에 있습니다.

### 선택 Secret

필요할 때만 3단계와 같은 방법으로 추가합니다.

| Name | 언제 쓰나 |
|---|---|
| `RESTAURANT_CODE` | 식당을 직접 지정할 때 (예: `REST000595` = 전기부산) |
| `RESTAURANT_NAME` | 식당을 이름으로 찾을 때 (예: `멀티캠퍼스`). 결과가 여러 개면 실행이 멈추고 후보 목록을 로그에 보여줌 → 거기서 코드를 골라 `RESTAURANT_CODE`에 넣기 |
| `HALL_NO` | 표에 넣을 코스 구역 코드. 기본 `E32M` (전기부산의 점심 코스). 다른 식당이면 바꿔야 함 |

식당을 지정하지 않으면 웰플러스 앱에서 내가 등록해둔 식당 중 첫 번째를 씁니다.
지정한 식당이 내 계정에 없으면 자동으로 등록합니다.

**다른 식당을 쓸 때:** `HALL_NO`를 모르면 일단 `dry_run`을 실행하세요.
`HALL_NO=E32M 에 해당하는 코스 없음. 응답에 있는 홀: [...]` 로그가 나오면, 그 목록 중 점심 코스 구역 코드를 `HALL_NO`에 넣으면 됩니다.

## 문제 해결

Actions 탭에서 실패한(빨간 X) 실행 → **식단 조회 및 전송** 단계를 열고 `오류:`로 시작하는 줄을 찾습니다.

| 로그 메시지 | 원인 | 해결 |
|---|---|---|
| `환경변수 ... 없음` | Secret이 없거나 이름이 틀림 | 3단계 표와 이름이 똑같은지 확인 |
| `로그인 실패 … 아이디/비밀번호를 확인해주세요.` | 계정 정보가 틀림 | 웰플러스 앱에서 로그인되는지 확인 후 Secret 다시 입력 |
| `MM_WEBHOOK_URL 형식 오류` | 채널 주소를 넣었거나 오타 | `/hooks/`가 들어간 주소인지 확인 |
| `웹훅 xxxxxxxx … 실패: HTTP 4xx` | 웹훅이 삭제/비활성화됨 | Mattermost 통합 메뉴에서 웹훅 확인 |
| `HALL_NO=… 에 해당하는 코스 없음` | 식당의 코스 구역 코드가 다름 | [선택 Secret](#선택-secret)의 "다른 식당을 쓸 때" 참고 |
| `'…' 검색 결과가 N개라 하나로 못 정함` | `RESTAURANT_NAME`이 여러 식당에 걸림 | 로그의 후보 중 코드를 `RESTAURANT_CODE`에 넣기 |
| `방화벽(Incapsula)이 요청 차단` | 웰스토리 보안 장비가 요청을 막음 | 잠시 뒤 다시 실행. 계속되면 웰스토리 정책이 바뀐 것 |
| `빈 응답`, `JSON이 아닌 응답`, `'중식/점심' 없음` | 웰스토리 API가 바뀜 | `dry_run`으로 실행해 로그를 보고 코드 수정 필요 |

실패가 아닌데 메시지가 없을 때:

| 상황 | 원인 | 해결 |
|---|---|---|
| 실행 기록 자체가 없음 | 예약 실행 지연/누락, 또는 Actions가 꺼짐 | [직접 실행하기](#직접-실행하기)에서 `no_wait`로 실행. 꺼져 있으면 4단계 |
| 성공(초록 체크)인데 메시지 없음 | 메뉴 없는 날 (`식단 없음` 로그) | 정상 |
| 성공인데 `이미 전송됨` 로그 | 오늘 이미 보냄 | 정상. 한 번 더 보내려면 `force` |

## 참고

- **Actions 사용 시간:** private 레포는 GitHub 무료 한도(월 2,000분) 안에서 실행 시간이 차감됩니다. 이 봇은 하루 최대 약 10분, 월 약 220분을 씁니다. public 레포는 무료입니다.
- **public 레포의 자동 중지:** public 레포는 60일 동안 커밋이 없으면 GitHub가 예약 실행을 끕니다. 안내 메일이 오면 4단계처럼 다시 켜세요. private 레포는 해당 없습니다.
- **템플릿 대신 포크해도 되나요?** 됩니다. 다만 포크는 Actions가 꺼진 채로 시작하므로 4단계를 꼭 하세요.
- **보안:** 비밀번호, 로그인 토큰, 웹훅 URL은 로그에 찍히지 않습니다. 웹훅은 앞 8자리 해시로만 표시됩니다.

## 개발자용: 내 PC에서 실행하기

Node 20 이상이 필요하고, 설치할 패키지는 없습니다 (Node 내장 `fetch`만 사용).

```sh
cp .env.example .env          # .env에 Secret과 같은 값을 채우기
node lunch_bot.mjs --dry-run           # 보내지 않고 메시지(JSON)만 출력
node lunch_bot.mjs --dry-run --debug   # 웰스토리 API 원본 응답까지 출력
node lunch_bot.mjs --no-wait           # 사진 기다리지 않고 바로 전송
```

| 옵션 | 설명 |
|---|---|
| `--dry-run` | 보내지 않고 메시지(JSON)만 출력. 사진 대기 없음 |
| `--debug` | 웰스토리 API 응답 원문을 로그에 출력 |
| `--no-wait` | 사진 대기 없이 바로 전송 |
| `--date YYYYMMDD` | 다른 날짜 조회 (기본: 오늘, 한국 시간) |
| `--sent-marker 파일` | 전송 기록 파일. 같은 날 같은 웹훅으로 두 번 보내지 않음 |

`.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다. 이미 설정된 환경변수가 있으면 `.env`보다 우선합니다.

**왜 Python이 아니라 Node인가:** 웰스토리 로그인 주소 앞단의 방화벽(Imperva Incapsula)이 Python `requests` 요청을 403으로 막습니다. 같은 요청을 Node 내장 `fetch`나 curl로 보내면 통과합니다.
